# Android UI Style

SmartFeed Android 首页采用 Cozy Journal 手账风。迁移 HTML 参考稿时优先保留视觉语言，但不虚构当前没有的产品能力。

## Style Direction

- 整体观感：温暖、轻松、私人知识手账。
- 背景：奶油纸张底色，后续可加入轻量纸张纹理；不要改成纯 Material 默认白底。
- 色彩：使用柔和莫兰迪色，避免高饱和科技蓝或大面积紫色渐变。
- 形状：大圆角、贴纸式长卡片、悬浮底部导航。
- 字体：引入 HTML 参考稿里的 Nunito 和 Kalam 字体资源；Nunito 用作主 UI 字体，Kalam 用于 `Morning!`、相对时间、当前分类等手写感细节。

## Locked Visual Details

- 顶部保留 `Morning!` 问候、太阳符号、`SmartFeed` 标题和标题装饰线。
- 右上角保留圆形虚线风格入口，可用于 Profile 或状态入口。
- 顶部搜索栏放在 Header 下方、URL 卡片上方，占位文案为 `寻找记忆碎片...`。
- 上传入口保留黄色半透明贴纸卡片、顶部胶带、link 符号、白色输入框和深色提交按钮；胶带要跨出卡片上沿，形成“把卡片贴到纸面上”的效果。
- 最近内容保留 topic pills：选中项深色，未选中项白底描边。
- 最近内容卡片统一使用长卡片，不使用半宽双列卡片。
- 卡片保留莫兰迪绿、蓝、粉、黄等不透明淡色背景、内部更深的同色系不规则装饰形状和贴纸阴影；装饰形状必须被卡片圆角裁剪，不要露出卡片边界。
- 底部导航保留白色半透明胶囊和中间凸起的砖红色新聊天按钮；导航必须作为覆盖式浮层绘制在页面上，不使用 `Scaffold bottomBar` 占位，避免产生白色截断区域。
- 图标使用 Compose Material Icons Extended，不使用中文字符或纯文本符号替代。

## Product Data Rules

- 不显示当前没有的功能字段。
- HTML 参考里的“评论”不照搬；当前可显示 conversation 的消息数，例如 `2 条消息`。
- HTML 参考里的“划线”不照搬；当前可显示 `storedChunks`，例如 `23 片段`。
- 时间使用真实 `updatedAtMillis` 转成相对时间。
- topic 使用真实 `conversation.topic`，没有 topic 时使用本地 fallback。
- 标题和摘要使用真实 `conversation.title`、`conversation.summary`。
- 搜索框使用当前 Home 本地 conversation 搜索能力。
- 上传卡片继续绑定现有 `url`、`onUrlChange`、`onUpload` 和上传状态。
- 首页文章速记与生成它的 URL 绑定；从聊天页返回时继续显示，只有 URL 清空或改为其他 URL 时才清除。
- 底部导航继续使用现有 5 个入口：`首页`、`文章`、`新聊天`、`分析`、`我的`。

## Article Library

- 文章页沿用首页的纸张背景、Nunito/Kalam 字体、莫兰迪配色和悬浮导航。
- 圆角搜索框直接放在标题下方，排序使用搜索框右侧的图标按钮。
- 分类使用横向胶囊按钮，不使用默认 Material Tab 指示器。
- 文章卡片只展示真实标题、域名、topic 和 chunk 数；胶带、回形针、图钉和纸张纹理仅作为装饰，不虚构业务字段。
- 保留点击打开文章聊天和左滑删除，列表底部为悬浮导航预留空间。

## Analysis Journal

- `analysispage.html` 只定义视觉方向，不定义功能范围；不得因为参考稿未展示而删除现有分析模块。
- 保留智能总结及其来源、亮点和建议，使用带胶带和方格纸纹理的便签卡片。
- 保留真实 topic 分布和图例，使用莫兰迪色甜甜圈图，不写死参考稿中的比例或主题数量。
- 保留知识库画像、内容厚度排行和来源网站分布，并使用同一套纸张卡片、标签和信息条样式。
- 右上角入口继续打开文章管理页；加载、空数据和错误状态必须保留。
- 页面底部为覆盖式悬浮导航预留空间，不使用导航占位截断内容。

## Cozy Chat

- 保留返回、打开原网页、流式状态、所有消息类型、回答依据展开和发送输入等现有聊天能力。
- 文章总结使用独立的胶带便签卡片，与普通 AI 回复区分；卡片可使用轻量方格纸纹理和虚线分隔。
- Markdown 继续使用现有 renderer，不降级为纯文本；标题、正文、引用、列表、链接、行内代码和代码块分别应用 Nunito/Kalam、等宽字体及莫兰迪颜色。
- 普通 AI 回复使用白色纸张气泡和叶片头像，用户消息使用深色气泡；不要让所有消息都变成大型卡片。
- 回答依据使用虚线引用块，继续支持展开详情和打开原网页。
- 不增加没有实际行为的附件或工具按钮。

## Profile Journal

- 页面标题固定为手写 `Hello Traveler!` 和主标题 `我的主页`。
- 个人页默认使用显示名或邮箱首字母生成头像，也支持从系统相册选择头像；图片 URI 按账号保存在本机，不上传到服务端。
- 头像卡使用淡粉色手账卡和右上蓝色书签装饰，只显示昵称与个人简介，不显示邮箱或虚构的会员标签。
- 头像编辑和昵称/简介编辑使用同一个资料弹窗；头像旁编辑按钮保持小尺寸，不拆成两个入口。
- 账号信息卡紧接头像卡下方，保留真实邮箱和加入时间，邮箱作为登录身份只读展示。
- 概览只展示两个并排纸卡：真实文章数和真实对话数，不显示消息数与碎片数。
- 文章管理、知识分析和新聊天快捷入口必须连接现有导航与业务行为。
- 昵称与个人简介通过 `PATCH /auth/me` 持久化，保存期间显示进度，失败时保留编辑内容。
- 退出登录需要二次确认，不删除已同步的云端数据。

## Bottom Navigation Touch Targets

- 保持现有图标、选中圆形和中间加号的视觉尺寸不变。
- 普通 Tab 使用至少 `54dp` 的透明触控区域，中间新增按钮使用 `82dp` 的透明触控区域，减少误触和漏触。

## Implementation Scope

- 当前优化范围包括 Home、Article Library 和 Bottom navigation。
- 不改后端 API。
- 不改上传、聊天、文章同步、Room 或 WebSocket 业务逻辑。
- 不新增未确认的页面能力。
- Compose 实现可以用近似方案模拟 HTML 细节，例如 Canvas 波浪线、虚线圆形边框、下载字体资源和 Material 图标。
